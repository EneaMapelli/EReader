## Known constraints and gates

- **No Flutter or Dart SDK and no Windows/Android native toolchains in execution environment:** no build, analyzer or device tests have been run; CI workflow is manually triggerable and must provide evidence before feature completion.
- Native `android/` and `windows/` platform folders are generated by `flutter create` using scripts, not checked in yet. Generate/commit these before release. This is **not** a drop-in buildable checkout without bootstrapping.
- SQLite 3.x schema v9 backs the library with transactions, a serialized source anchor plus legacy global UTF-16 offset, and migrations from schema v1 and `library.json`. Actual Windows/Android migration/recovery tests remain unexecuted.
- EPUB reading uses OPF spine ordering and source anchors (spine ID + relative UTF-16 offset). This is more stable than an absolute extraction offset but not a full EPUB CFI anchor; XHTML formatting, notes, illustrations and corpus tests remain outstanding.
- PDF page view and optional read-aloud extraction are present for selectable-text PDFs; text order in columns/tables is unverified and page-accurate synchronized highlighting is unavailable. Scans require OCR.
- System voices are OS dependent; Android pause/resume restarts a sentence chunk and background audio requires further integration.
- The OpenAI speech engine, secure key vault and explicit per-book cloud authorization are now present as code; no real API calls or costs were incurred in development. The default remains system TTS with no cloud access.
- Imported books have a 100 MB prototype limit; EPUB extraction checks declared uncompressed resource sizes and ZIP paths, but ZIP fuzz testing remains a release gate.
- The documentation contains approved **future** features, not implemented ones.

## P0 update — source-relative reading anchors (2026-10-22)

- Added `ReadingAnchor` (v1 serialized model) for TXT body, EPUB spine idref and PDF page number. Each anchor stores a UTF-16 code-unit offset relative to its source, not a global concatenated document offset.
- `DocumentContent.anchorAt` and `offsetOf` map positions; missing/unknown sources return null so reopening can fall back to the old global offset. The source is linked to the current book's file hash, not independently transferable between different books.
- SQLite migration v1 → v2 adds `progress_anchor` without discarding `progress_offset`; imported legacy JSON still works. Playback and manual segment seek both persist source-relative anchors.
- Added unit tests for EPUB chapter offset drift, PDF page anchor round-trip, invalid anchors, legacy JSON/SQLite migration and restoration across restarts.
- **Status:** source changes have been verified by reading the GitHub files, but tests and compiler remain **not executed**. Windows/Android runner generation and successful manual verification are the next quality gate.


## P0 update — visual reading progress (2026-10-22)

- In visual mode (when TTS is not playing), EReader now observes the top visible speech segment and persists its source anchor in SQLite after a short debounce. This avoids committing continuously while scrolling.
- Pressing Play after manual scrolling starts at that visible segment. While audio is playing, visual scrolling does not change the audio cursor; pause/resume retains the current audio segment.
- Manual scroll progress is approximate at **segment granularity**, not pixel or word granularity; full pagination and EPUB CFI navigation remain out of scope for M0.
- The API surface of `scrollable_positioned_list` was checked against the package reference. **Widget interaction and real Windows/Android audio playback have not been tested.**

## M3 provider integration — 2026-10-22

Detailed design: [TTS Provider Integration](TTS_PROVIDER_INTEGRATION.md).

- System TTS and OpenAI Speech are selected via a shared SpeechEngineFactory. Persisted SpeechPreferences now include the model ID, with backward-compatible defaults.
- OpenAI Audio Speech adapter sends short text chunks to the fixed HTTPS speech endpoint and plays returned MP3 using just_audio with Windows platform adapter. This code has **not** been run against the live API or on devices.
- Keys are saved with flutter_secure_storage; neither the book database nor any source file contains a real credential. The UI can save, replace and remove the key without revealing it.
- SQLite schema v5 enforces a separate, default-deny consent record and local hard character quota per book/provider. Characters are reserved atomically before cloud HTTP; failed attempts still consume local quota. This is not an account billing ceiling.
- Each book has a settings screen to choose system vs OpenAI, choose one of the API-supported speech models, explicitly authorize or revoke transmission, view usage and erase locally generated audio.
- Private MP3 cache reuses previous synthesis for the exact book, voice, model and text; repeat playback does not reissue HTTP or spend new quota. The cache has a 250 MiB cap across books and supports per-book deletion.
- OpenAI pitch is disabled in the reader UI; the speech endpoint does not supply word-level timestamps, and exact verbatim output is not yet proven.
- Security hardening: HTTPS fixed endpoint, redirects disabled, sanitized status errors (no provider response body), bounded 20 MiB streamed audio responses, generation token prevents stale playback after Stop.
- Added mock HTTP/audio/vault and SQLite tests for consent, revocation, quotas, key missing, cached repeats, cancellation, secret isolation, storage migrations and cache path safety. **Tests not executed**; builds intentionally deferred to final integration.

- Added CastSpan with exact UTF-16 source start/end, SHA-256 excerpt fingerprints, character ID or unknown, source anchor, origin (user/llm), review status, confidence and manual lock.
- SQLite v7 adds cast_spans, separate from legacy whole-segment casting. Migration preserves all previous tables and data. New manual annotations must match the current source and cannot overlap another manual lock.
- The reader now splits source speech segments at approved fine-grained intervals and switches character voices only for those intervals. Narration and explicitly unknown fragments use the narrator; proposals still pending/rejected never affect audio.
- Voice Cast now includes mouse/touch text selection inside a passage dialog, plus a Review tab listing approved fine-grained labels and pending speaker proposals. Users can delete accepted labels, review suggestions or import structured JSON locally.
- The CastProposalParser validates schema/book ID, known cast member IDs, per-excerpt hashes, UTF-16 boundaries, confidence and payload limits. The parser NEVER invokes an LLM or remote service; suggestions cannot approve themselves.
- Manual labels override already approved LLM suggestions via a transactional downgrade of conflicting machine labels; accepting a conflicting proposal is rejected. Explicit unknown/narrator ranges mask legacy speaker labels.
- The interval resolver checks source drift, prevents half-surrogate (emoji) splitting, conservatively ignores invalid overlaps and indexes nearby labels rather than checking every label against every speech segment.
- Authored domain tests for source-hash mismatches, nonoverlap, Unicode, origin/review state and untrusted LLM response validation, plus SQLite v6→v7 migration and locked-user precedence tests. These are NOT executed.

## M5 opt-in dialogue analysis implementation — 2026-10-23

Design and privacy contract: [LLM Dialogue Analysis](LLM_DIALOGUE_ANALYSIS.md).

- Added real OpenAI Responses adapter with strict JSON-schema speaker proposals and model whitelist (gpt-5.4-mini / gpt-5.4-nano). No automatic network calls, no tools and store=false; transport handles HTTP failures without exposing book text/error bodies.
- Added `DialogueAnalysisPlanner` for explicitly selected EPUB spine chapters, PDF pages or bounded TXT windows. Per-call book excerpt maximum ~4,200 UTF-16 code units, up to 80 segments; only the selected window and local known character names/aliases are supplied.
- The model supplies original segment index + a verbatim, unambiguous substring. Exact source positions, source fingerprints and validation against existing characters are calculated locally before saving as proposals; hallucinated snippets/IDs are rejected.
- SQLite schema v8 stores default-deny per-book analysis consent and a transactional attempted input-character budget, entirely separate from paid TTS consent, reservations and API key. Quota is not a token/monetary spending limit and cannot control generated-output billing.
- New UI shows model/scope and next excerpt window, separate secure API key, explicit permission dialogue, character counters and per-request passage preview/confirmation. Requests are single-window only, never full-book background jobs.
- Model suggestions are persisted only as proposed spans in the existing review queue; **no voice changes without individual approval**. Existing manual corrections stay authoritative.
- Added mocked HTTP, planner and SQLite v7→v8 migration tests. These were authored but NOT executed, and no external LLM request was made in this development session.

**Still missing:** verified builds and tests; actual on-device SSL/storage smoke checks, cross-chapter inference, spoiler/context controls, output-token monetary budgeting and automatic named-character discovery. Final compilation remains postponed by explicit owner direction.

## M5 context and spoiler-control increment — 2026-10-23

- By default, model analysis cannot read past the **saved reading position**. The user may explicitly override the cap only for the chosen chapter, PDF page or TXT range, never later material. Target windows cannot cross the cap.
- Optional preceding context is limited to zero (default), 400 or 900 UTF-16 characters **within the same chosen scope**. No forward context is ever sent. It is shown in the per-request preview and counted against the independent LLM input budget.
- Character/alias allowlist is empty by default: only people explicitly selected as already known are sent with the request. Unknown future cast members are excluded.
- The model may cite a previous context segment and exact quote as source-grounded speaker evidence. The client computes the original UTF-16 offset and SHA-256, rejects invented or ambiguous evidence, and stores provenance in SQLite v9.
- The review UI displays citations and disables approval if evidence no longer matches source. On explicit approval, both the proposed text and evidence are revalidated.
- Additional planned but **unexecuted** tests cover backward-only context, caps, forged future context, evidence tampering, and SQLite v8-to-v9 migration.
- Caveat: this limits the transmitted text and character names, not what the model might infer from visible content; it is not a mathematical guarantee against narrative spoilers. Native builds/Flutter tests remain postponed to final integration by the owner.
