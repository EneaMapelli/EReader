## Known constraints and gates

- **No Flutter or Dart SDK and no Windows/Android native toolchains in execution environment:** no build, analyzer or device tests have been run; CI workflow is manually triggerable and must provide evidence before feature completion.
- Native `android/` and `windows/` platform folders are generated by `flutter create` using scripts, not checked in yet. Generate/commit these before release. This is **not** a drop-in buildable checkout without bootstrapping.
- SQLite 3.x schema v2 backs the library with transactions, a serialized source anchor plus legacy global UTF-16 offset, and migrations from schema v1 and `library.json`. Actual Windows/Android migration/recovery tests remain unexecuted.
- EPUB reading uses OPF spine ordering and source anchors (spine ID + relative UTF-16 offset). This is more stable than an absolute extraction offset but not a full EPUB CFI anchor; XHTML formatting, notes, illustrations and corpus tests remain outstanding.
- PDF page view and optional read-aloud extraction are present for selectable-text PDFs; text order in columns/tables is unverified and page-accurate synchronized highlighting is unavailable. Scans require OCR.
- System voices are OS dependent; Android pause/resume restarts a sentence chunk and background audio requires further integration.
- No cloud call, API key storage, book upload or cost incurred in this increment.
- Imported books have a 100 MB prototype limit; EPUB extraction checks declared uncompressed resource sizes and ZIP paths, but ZIP fuzz testing remains a release gate.
- The documentation contains approved **future** features, not implemented ones.

## Validation checklist (run on Windows + Android)

1. Run tool/bootstrap script and `flutter pub get` (includes sqlite3 3.x native assets).
2. `flutter analyze` and `flutter test` clean, including EPUB reading-order and safety tests.
3. On each OS import TXT + EPUB + PDF, switch PDF into experimental text read-aloud mode, close/reopen and retain the SQLite library and progress.
4. Read one chapter with TTS system; pause/seek/resume; verify displayed segment and progress after restart.
5. Confirm offline behavior (no remote calls).
6. Validate at least 10 EPUBs and 10 PDFs for failures or ordering problems; capture defect list.

## P0 update — source-relative reading anchors (2026-10-22)

- Added `ReadingAnchor` (v1 serialized model) for TXT body, EPUB spine idref and PDF page number. Each anchor stores a UTF-16 code-unit offset relative to its source, not a global concatenated document offset.
- `DocumentContent.anchorAt` and `offsetOf` map positions; missing/unknown sources return null so reopening can fall back to the old global offset. The source is linked to the current book's file hash, not independently transferable between different books.
- SQLite migration v1 → v2 adds `progress_anchor` without discarding `progress_offset`; imported legacy JSON still works. Playback and manual segment seek both persist source-relative anchors.
- Added unit tests for EPUB chapter offset drift, PDF page anchor round-trip, invalid anchors, legacy JSON/SQLite migration and restoration across restarts.
- **Status:** source changes have been verified by reading the GitHub files, but tests and compiler remain **not executed**. Windows/Android runner generation and successful manual verification are the next quality gate.
