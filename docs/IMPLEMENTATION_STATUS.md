## Known constraints and gates

- **No Flutter or Dart SDK and no Windows/Android native toolchains in execution environment:** no build, analyzer or device tests have been run; CI workflow is manually triggerable and must provide evidence before feature completion.
- Native `android/` and `windows/` platform folders are generated by `flutter create` using scripts, not checked in yet. Generate/commit these before release. This is **not** a drop-in buildable checkout without bootstrapping.
- Prototype index is JSON and doesn't provide SQLite transactions; migrate to SQLite and use crash-safe commits before M1 completion.
- EPUB parser currently flattens chapters into text; it does not preserve the EPUB CSS/illustrations, reliable spine ordering, CFI anchors and TOC reading position. No production claim.
- PDF only visual, no extracted text for TTS; page-accurate read along unavailable.
- System voices are OS dependent; Android pause/resume restarts a sentence chunk and background audio requires further integration.
- No cloud call, API key storage, book upload or cost incurred in this increment.
- Imported books are copied to application support; prototype limit 100 MB and no EPUB decompression-ratio protections yet.
- The documentation contains approved **future** features, not implemented ones.

## Validation checklist (run on Windows + Android)

1. Run tool/bootstrap script and `flutter pub get`.
2. `flutter analyze` and `flutter test` clean.
3. On each OS import TXT + EPUB + PDF (PDF visual only), close/reopen and retain library.
4. Read one chapter with TTS system; pause/seek/resume; verify displayed segment and progress after restart.
5. Confirm offline behavior (no remote calls).
6. Validate at least 10 EPUBs and 10 PDFs for failures or ordering problems; capture defect list.
