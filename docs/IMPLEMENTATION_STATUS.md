## Known constraints and gates

- **No Flutter or Dart SDK and no Windows/Android native toolchains in execution environment:** no build, analyzer or device tests have been run; CI workflow is manually triggerable and must provide evidence before feature completion.
- Native `android/` and `windows/` platform folders are generated by `flutter create` using scripts, not checked in yet. Generate/commit these before release. This is **not** a drop-in buildable checkout without bootstrapping.
- SQLite 3.x schema v13 backs the library with transactions, a serialized source anchor plus legacy global UTF-16 offset, and migrations from schema v1 and `library.json`. Actual Windows/Android migration/recovery tests remain unexecuted.
- EPUB reading uses OPF spine ordering and source anchors (spine ID + relative UTF-16 offset). This is more stable than an absolute extraction offset but not a full EPUB CFI anchor; XHTML formatting, notes, illustrations and corpus tests remain outstanding.
- PDF page view and optional read-aloud extraction are present for selectable-text PDFs; text order in columns/tables is unverified and page-accurate synchronized highlighting is unavailable. Scans require OCR.
- System voices are OS dependent; Android pause/resume restarts a sentence chunk and background audio requires further integration.
- The OpenAI speech engine, secure key vault and explicit per-book cloud authorization are now present as code; no real API calls or costs were incurred in development. The default remains system TTS with no cloud access.
- Imported books have a 100 MB prototype limit; EPUB extraction checks declared uncompressed resource sizes and ZIP paths, but ZIP fuzz testing remains a release gate.
- The documentation contains approved **future** features, not implemented ones.

## M5 context and spoiler-control increment — 2026-10-23

- By default, model analysis cannot read past the **saved reading position**. The user may explicitly override the cap only for the chosen chapter, PDF page or TXT range, never later material. Target windows cannot cross the cap.
- Optional preceding context is limited to zero (default), 400 or 900 UTF-16 characters **within the same chosen scope**. No forward context is ever sent. It is shown in the per-request preview and counted against the independent LLM input budget.
- Character/alias allowlist is empty by default: only people explicitly selected as already known are sent with the request. Unknown future cast members are excluded.
- The model may cite a previous context segment and exact quote as source-grounded speaker evidence. The client computes the original UTF-16 offset and SHA-256, rejects invented or ambiguous evidence, and stores provenance in SQLite v9.
- The review UI displays citations and disables approval if evidence no longer matches source. On explicit approval, both the proposed text and evidence are revalidated.
- Additional planned but **unexecuted** tests cover backward-only context, caps, forged future context, evidence tampering, and SQLite v8-to-v9 migration.
- Caveat: this limits the transmitted text and character names, not what the model might infer from visible content; it is not a mathematical guarantee against narrative spoilers. Native builds/Flutter tests remain postponed to final integration by the owner.

- From Voice Cast > **Dialogues**, the new detailed-turn editor pages through EPUB chapters, PDF pages and TXT ranges in bounded 12k UTF-16 source windows (up to 100 turns per window), continuing after the last seen turn when capped.
- It detects guillemet/curly/ASCII quotations and line-start em/en dash dialogue; marks interruptions (dash or ellipsis), unfinished/truncated turns, partial source-tag coverage, conflicting approved voices, explicit narrator and multiple confirmed speakers in one turn. It never guesses or propagates speaker identities.
- Every status corresponds to a source-verified subspan. LLM-pending, non-locked or stale annotations cannot drive confirmed display. Original book text, UTF-16 offsets and source hashes remain unchanged.
- Fully unlabeled **complete** turns have an explicit manual voice/narrator action. Existing LibraryStore.saveManualCastSpan enforces SHA-256, book ownership and no silently overwritten manual locks; partial/conflicted/unfinished turns remain review-only and are corrected via precise Passages editing.
- Added **14 unexecuted domain tests** (test/domain/dialogue_turn_review_test.dart) and **3 unexecuted SQLite integration tests** (test/data/dialogue_turn_review_store_test.dart) covering punctuation, partial/switch/conflict distinctions, UTF-16, anchors, persistence, stale book source and locked-overlap rollback.
- No schema migration or cloud call. Flutter tests, analyzer and native Windows/Android builds remain deferred until final integration as instructed.

## M5 — cross-chunk TTS dialogue voice continuity (2026-10-23)

Design and limitations: [Cross-Chunk TTS Casting](CROSS_CHUNK_TTS_CASTING.md).

- Reworked the reader speech plan to preserve shared quotation-region IDs across underlying 400-character source chunks. Quotations spanning multiple chunk boundaries no longer rely on an exact whole-segment match to determine the voice.
- Legacy whole-passage segment_cast labels are now verified as **source-hashed ranges**, optionally relocated using reading anchors, and split into per-chunk speaker choices alongside accepted locked fine-grained CastSpan annotations. Wrong-book IDs, missing roster entries, stale source and overlapping legacy assignments are discarded.
- Fine-grained human voice/narrator overrides take priority. Disputed fine labels additionally suppress obsolete legacy fallback within contested source ranges. ReaderScreen no longer re-evaluates legacy exact-chunk labels after the plan has been prepared.
- Sequential fragments are coalesced **only within the same quoted turn**, with an identical verified speaker/mask and whitespace-only gaps, and only when the resulting original source text is at most 400 UTF-16 units. This reduces synthesis hand-offs without merging different quoted turns or changing read-along source offsets.
- ReaderPlayer already changes provider/native voice only when the voice key changes. The new mock playback test asserts continuity across several long-quote chunks and narrator restoration.
- Added 12 unexecuted source-domain tests in test/domain/cross_chunk_cast_test.dart and one unexecuted mocked engine test in test/audio/reader_player_test.dart; no on-device audio or gapless waveform promises are made.
- No SQLite migration, automatic cast inference, cloud request or consent change. Flutter analyzer/tests, Windows/Android compilation and audible TTS hand-off tests remain deferred until final integration.

## M5 — one-ahead cloud audio prebuffer, explicit opt-in (2026-10-23)

Protocol: [Cloud TTS Prefetch](CLOUD_TTS_PREFETCH.md).

- Added an optional `AheadOfTimeSpeechEngine` capability implemented only by OpenAiSpeechEngine. It asynchronously prepares at most one future, immutable model/voice/text MP3 clip while keeping the actual audio output serialized.
- ReaderPlayer passes the next segment's pronunciation-transformed speech text and verified cast/narrator voice. Prefetch is **OFF by default** and enabled only by a separate session checkbox in ReaderScreen when OpenAI Speech is selected. The UI explicitly discloses that future text may incur cloud quota/charges before it is heard.
- The cloud engine waits until the current audio is successfully rendered and is ready to start output before starting a paid lookahead. A failed first clip therefore cannot schedule a second paid request. Lookahead still uses the existing book-scoped consent, secure API key, immutable model/voice/text SHA-256 cache key, attempted-character reservation and MP3 size cap.
- When the matching next clip is played, the engine consumes its prepared Future/result without re-requesting or re-reserving. A failed lookahead is surfaced on that next segment rather than automatically retrying at additional cost.
- Pause, seek, stop and dispose invalidate generations and suppress stale future audio. Consent is rechecked before playing prepared bytes; revocation produces an error, not silent skipped narration. An HTTP request already submitted cannot be guaranteed cancelled or unbilled.
- Added seven mocked tests (test/audio/cloud_prefetch_test.dart), **authored but not executed**, for default-deny, gated scheduling, different next character voice, network failure without paid retry, consent revocation, pause/seek and failed first clip.
- The initial cloud prebuffer overlapped HTTP synthesis; an additional dual-decoder increment now allows the next already-synthesized private MP3 file to load on an idle decoder. This still does **not** guarantee gapless Windows/Android playback or eliminate OS/native TTS pauses. Windows/Android and Flutter integration remains deferred.

## M5 — dual MP3 decoder warm-up for shorter clip handoffs (2026-10-23)

Protocol: [MP3 Decoder Preload](MP3_DECODER_PRELOAD.md).

- Introduced an optional `PreloadableSynthesizedAudioOutput`: the existing cloud one-ahead render now also calls `prepareNext` on an idle local decoder with the identical already-synthesized MP3 bytes and next playback speed. This causes **no extra HTTP request or quota reservation**.
- Refactored `JustAudioMp3Output` to two reusable `just_audio` players: one outputting the current clip, the other loading the immediately following file. Source stays in private temporary storage; two-player serial playback preserves the existing per-segment speaking, read-along and progress semantics.
- A warm match uses the standby player without calling native `setFilePath` again. Unexpected text or speed invalidates its warm source, so later prefetches can resume. Pause, stop and dispose invalidate playback, stop native decoders and remove temporary files, with retry of Windows file-lock deletion.
- Native system TTS does not change. The explicit **OFF-by-default** cloud prebuffer permission and warning about billable *unheard* text remain unchanged. No new consent, SQLite migration or hidden background job was added.
- Authored **8 new unexecuted tests** in `test/audio/mp3_preload_test.dart`, using injected mock decoders/filesystem, plus extended 7 existing unexecuted cloud prefetch tests to assert that cloud MP3 bytes reach the decoder warm-up hook.
- Native API support was reviewed against `just_audio` 0.10.x documentation, but source formatting, Flutter analyzer/tests, Windows/Android real builds, MP3 waveform boundaries, foreground/background transitions and Windows file locks are still unverified.

## M5 — race-safe playback navigation and decoder generations (2026-10-23)

Protocol: [Playback Session Safety](PLAYBACK_SESSION_SAFETY.md).

- ReaderPlayer now separates speaking-session invalidation from **latest-wins navigation epochs**. Rapid overlapping seek calls cannot restore old positions or auto-resume from stale requests; an explicit Pause or Play supersedes a pending seek while native Stop operations remain serialized.
- Rapid native voice choices are serialized, with canceled old completions unable to establish the next playback voice. Choosing a voice while playing resumes the current segment with the winning voice; while paused it stays paused. Failure clears pending resume. Disposal is idempotent and blocks new Play.
- Reader controls restart the *current* source segment when rate/pitch sliders are released or language is changed, not on every drag tick. This invalidates pending prebuffer generations and reasserts the correct narrator/cast voice without altering book text or anchors.
- The dual MP3 decoder now serializes pending native loads and old end-of-clip cleanup per decoder slot. Generation checks around slow native Stop and file deletion prevent an old playback finalizer from stopping or deleting a newly active source.
- Authored **9 unexecuted navigation/voice tests** in test/audio/rapid_playback_navigation_test.dart; extended test/audio/mp3_preload_test.dart to **10 unexecuted decoder tests** including old-finalizer/new-play and late-old-load/new-MP3 isolation.
- No additional cloud synthesis, new SQLite schema or background job. Previously transmitted audio requests may still be billable after cancellation; Flutter tests/analyzer and Windows/Android runtime tests remain postponed until final integration.

## M2 — session sleep timer (2026-10-23)

- Added a **10/15/30/45/60-minute sleep timer** to the in-reader playback controls. Choosing another duration replaces the old deadline, and a visible menu entry cancels it.
- Deadline is explicitly **wall-clock time**: manual pause does not extend it. It is session-only; leaving the reader or completing the book removes it. No background service, fade-out or persistent alarm is claimed.
- Expiry calls the existing safe `ReaderPlayer.pause()` path to invalidate the playback session **before** awaiting a native stop. A late native completion cannot advance another passage. OpenAI audio prefetch still follows existing cancellation/consent rules; already-submitted paid HTTP work may finish.
- A configurable timer scheduler enables four deterministic, **authored but unexecuted** unit tests in `test/audio/sleep_timer_test.dart`: in-flight cancellation, replacing/cancelling deadlines, pause behavior, and natural completion/dispose.
- Windows/Android end-to-end verification, Flutter analyzer, real TTS stop latency, screen-off timer reliability and background-session behavior remain deferred to final integration as agreed. This timer is not a substitute for Media3 background playback.

## M2/M3 — Android foreground media session and headset controls (2026-10-23)

- Added Android-only `ReaderMediaHandler` and app initialization, using `audio_service 0.18.19` and `audio_session 0.2.4`, bridged to the existing `ReaderPlayer`; it does not create a second audio pipeline.
- Exposes Play, Pause, Stop, previous/next source segment plus the current book title to Android media notification, lock screen and headset interfaces. Drops controls when the reader page exits. Read along and cast attribution remain sourced from the same player.
- Uses a conservative pause-on-interruption/headphone-unplug policy and no auto-resume. Remote Play rechecks cloud consent and requests OS audio focus. Async Play is guarded against stale pause, attach/detach and late focus completion.
- Android service/activity/receiver and foreground permissions live in `tool/android/AndroidManifest.xml`; both bootstrap scripts install the template **after** generating the native platform project. Windows does not initialize audio_service.
- Added six **authored but unexecuted** transport, cloud consent, focus-race and teardown tests in `test/audio/reader_media_handler_test.dart`.
- Native compilation, Flutter tests, Android 12–16 foreground/doze behavior, media-key latency, notification lifecycle, Android Auto, process-death restoration and Windows regression builds are **not verified**. See [Android Background Media](ANDROID_BACKGROUND_MEDIA.md). No claim of a production-ready Media3 background feature yet.
